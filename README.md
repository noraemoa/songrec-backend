# 🎵 Noraemoa

> **자연어로 원하는 분위기와 상황을 입력하면, 사용자의 취향을 반영해 음악을 추천하는 개인화 음악 추천 서비스**

사용자가
`"비 오는 날 혼자 차 마시면서 듣기 좋은 노래"`
처럼 일상적인 문장으로 원하는 음악을 표현하면, 의미적으로 유사한 음악을 검색한 뒤 사용자 취향과 서비스 데이터를 함께 반영해 추천 결과를 제공합니다.

단순히 AI API를 호출하는 데서 끝내지 않고, 회원·음악·추천 요청·플레이리스트·좋아요·피드백 데이터를 직접 설계하고 REST API, 추천 로직, 인증, 외부 서비스 연동까지 백엔드 전반을 구현했습니다.

# 1. 프로젝트 목표

기존 음악 검색은 장르, 아티스트, 곡명처럼 정해진 조건을 직접 입력해야 하는 경우가 많습니다.

Noraemoa는 사용자가 원하는 상황과 분위기를 자연어로 표현할 수 있도록 하고,

1. 자연어의 의미를 분석하고
2. 의미적으로 유사한 음악을 탐색한 뒤
3. 사용자의 취향과 좋아요 이력을 함께 고려하여
4. 개인화된 추천 결과를 제공

하는 것을 목표로 개발했습니다.

---

# 2. 주요 기능

## 🎧 자연어 기반 음악 추천

사용자가 입력한 문장을 분석하여 검색에 필요한 감정, 상황, 장르 등의 정보를 추출하고 임베딩 벡터를 생성합니다.

생성한 벡터를 이용해 음악 후보를 검색하고, 검색 결과를 개인화 점수에 따라 재정렬합니다.

```text
자연어 입력
   ↓
검색 문장 분석
   ↓
Embedding 생성
   ↓
Vector Search
   ↓
추천 후보 조회
   ↓
Personalized Reranking
   ↓
최종 추천 결과
```

---

## 👤 사용자 취향 프로필

신규 사용자의 취향 정보가 부족한 Cold Start 문제를 완화하기 위해 회원가입 과정에서 음악 취향 정보를 수집합니다.

사용자의 선택 결과를 바탕으로 취향 태그와 프로필 정보를 생성하고 추천 과정에서 활용합니다.

추천에 활용하는 주요 정보:

* 사용자 취향 프로필
* 좋아요한 음악
* 검색어와 음악의 의미적 유사도
* 서비스 내 음악 반응
* 과거 추천 피드백

---

## 🔄 개인화 Reranking

초기 검색 결과를 그대로 반환하지 않고 여러 요소를 조합해 최종 추천 순서를 다시 계산합니다.

현재 추천 로직에서는 다음 요소를 활용합니다.

```text
Semantic Similarity
        +
User Profile Similarity
        +
Liked Track Similarity
        +
Popularity
        +
Past Feedback
        ↓
Final Recommendation Score
```

검색어와 유사한 음악을 찾는 것뿐 아니라, 같은 검색어를 입력하더라도 사용자 취향에 따라 서로 다른 결과를 제공할 수 있도록 설계했습니다.

## ❤️ 좋아요

## 📂 플레이리스트

* 플레이리스트 생성
* 수정 / 삭제
* 공개 여부 설정
* 음악 추가 / 삭제
* 공개 플레이리스트 조회
* 인기 플레이리스트 조회

---

## ⭐ 추천 피드백

추천받은 음악에 대해 사용자가 평가를 남길 수 있도록 구현했습니다.

평가 결과는 추천 요청과 음악의 관계에 저장하고, 유사한 과거 요청에 대한 사용자 반응을 이후 추천 점수에 활용할 수 있도록 구성했습니다.

---

## 📅 Daily Track

사용자가 하루의 음악을 기록하고 조회할 수 있는 기능을 구현했습니다.

* 일별 음악 기록
* 감정 정보 관리
* 연속 기록 조회
* 전날 기록 조회

---

## 🔐 인증 / 인가

Spring Security 기반으로 인증 구조를 구성하고 JWT를 이용해 API 접근을 제어합니다.

* 회원가입
* 로그인
* Access Token 기반 인증
* Refresh Token 관리
* 인증 실패 / 권한 부족 예외 응답 처리
